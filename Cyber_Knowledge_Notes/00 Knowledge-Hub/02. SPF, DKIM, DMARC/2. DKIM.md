# DKIM (Domain Keys Identified Mail)
## DKIM in One Sentence

**DKIM proves that the email was not changed and really came from the claimed domain.**

---

## DKIM Workflow (Very Short)

1️⃣ Email is created  
2️⃣ Sending mail server **signs the email** with a **private key**  
3️⃣ DKIM signature is added to email header  
4️⃣ Receiving mail server gets the email  
5️⃣ It looks up the **DKIM public key** in DNS (TXT record)  
6️⃣ It verifies the signature  
7️⃣ Result = **PASS or FAIL**

---

## Outcomes

### ✅ If DKIM PASSES

- Email content is **untouched**
    
- Sender domain is **verified**
    
- Helps pass **DMARC**
    
- Higher chance of **Inbox delivery**
    

### ❌ If DKIM FAILS

- Email was **altered** OR
    
- Signature/domain mismatch
    
- DMARC decides:
    
    - `none` → deliver with warning
        
    - `quarantine` → spam
        
    - `reject` → blocked
        

---

## What DKIM Checks (Important)

|DKIM Checks|DKIM Does NOT Check|
|---|---|
|Email content integrity|Sending IP|
|Domain authenticity|Server reputation|
|Digital signature|Email subject meaning|

---

## Very Simple DKIM Example

### Email Header (hidden)

```
DKIM-Signature: d=company.com; s=google;
```

### DNS DKIM Record

```
google._domainkey.company.com
TXT "v=DKIM1; k=rsa; p=MIIBIjANBgkq..."
```

Meaning:

- `d=` → domain signing email
    
- `s=` → selector (key name)
    
- `p=` → public key
    

---

## Key Rules to Remember 🧠

- DKIM uses **cryptography**
    
- **Private key** → signs email
    
- **Public key** → stored in DNS
    
- Email change = **DKIM FAIL**
    
- DKIM ≠ encryption (content is readable)
    

---

## SPF vs DKIM (One-Line Difference)

|SPF|DKIM|
|---|---|
|Who can send|Was message altered?|
|IP-based|Signature-based|
|Breaks on forwarding|Survives forwarding|
